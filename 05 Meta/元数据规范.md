# 元数据规范

## 通用结构

```yaml
---
type: concept
up: "<上级 MOC wikilink>"
area: differential-geometry
status: 初见
created: 2026-06-17
updated: 2026-06-17
aliases: []
prerequisites: []
helpful_prerequisites: []
related: []
sources: []
tags:
  - concept
---
```

## 必需属性

| 属性 | 含义 | 示例 |
|---|---|---|
| `type` | 笔记类型 | `concept` |
| `up` | 母页面或上级导航入口 | `"[[10 Maps/流形与微分几何 MOC|流形与微分几何 MOC]]"` |
| `status` | 成熟度或工作状态 | `可复述` |
| `tags` | 跨目录检索标签 | `concept` |

除 `Home.md` 和模板外，正式页面都应填写 `up`，用于从任意页面回到所属 MOC、索引或系统入口。概念、MOC、问题、练习和项目还应包含 `area`。

## 推荐属性

| 属性 | 含义 |
|---|---|
| `created` | 首次创建日期 |
| `updated` | 最近一次实质更新日期 |
| `aliases` | 英文名、别名和常见译名 |
| `prerequisites` | 必要前置概念 |
| `helpful_prerequisites` | 有助理解、但不阻塞当前主线的按需支撑 |
| `related` | 非前置的相关概念 |
| `sources` | 主要来源笔记 |
| `track` | 所属固定学习主线 |
| `order` | 在学习主线中的排序号 |
| `prev` | 学习主线中的上一页 |
| `next` | 学习主线中的下一页 |

## 硬前置与按需支撑

`prerequisites` 只记录**硬依赖**：缺少该知识时，当前页的定义、定理陈述或核心推导无法被正确理解。

`helpful_prerequisites` 记录**软依赖**：知道它会明显降低理解成本，但学习者可以先沿主线前进，在真正卡住时再补。

判断规则：

- 当前页公式直接使用了尚未定义的对象类型，通常属于 `prerequisites`；
- 只是为了提供更多直觉、熟悉例子或更方便的坐标计算，通常属于 `helpful_prerequisites`；
- “存在知识关系”不等于“必须先学完”；不要为了保险把所有相关概念都塞进 `prerequisites`。

例如，协向量拉回

$$
F_p^*:T_{F(p)}^*N\to T_p^*M
$$

直接使用余切空间，所以“余切空间”是硬前置；而熟悉矩阵转置有助于理解坐标公式 $J^T$，但不是定义成立的必要条件，因此更适合作为按需支撑。

## 主线导航属性

当一组页面属于固定学习顺序时，使用 `track`、`order`、`prev`、`next` 维护可校验导航。

```yaml
track: topology-prep
order: 20
prev: "[[20 Concepts/01 Topology/距离、邻域与开球|距离、邻域与开球]]"
next: "[[20 Concepts/01 Topology/开集、连续与同胚|开集、连续与同胚]]"
```

约定：

- `track` 使用小写英文短横线命名，例如 `topology-prep`；
- `order` 使用间隔数字，例如 `10`、`20`、`30`，方便中间插入新页；
- `prev` 与 `next` 使用带引号的 wikilink；
- 主线第一页的 `prev` 可留空，最后一页的 `next` 可指向下一条主线入口或留空；
- 正文导航由 [[90 Templates/导航块模板|导航块模板]] 根据 `prev` 与 `next` 生成；
- 校验脚本只作为备份手段，用于发现属性与正文导航长期漂移。

### Templater 导航块

固定主线页面设置好 `prev` 与 `next` 后，使用 Templater 插入 [[90 Templates/导航块模板|导航块模板]]。

模板会生成：

```markdown
## 导航
- 上一页：<上一页 wikilink>
- 下一步：<下一页 wikilink>
```

若 `prev` 或 `next` 为空，对应行不会输出；若两者都为空，则不输出导航块。

## type 允许值

`home`、`meta`、`moc`、`index`、`concept`、`theorem`、`method`、`learning-path`、`question`、`exercise-set`、`project`、`source`、`review`、`dashboard`、`roadmap`、`inbox`。

其中：

- `concept`：回答“对象、性质或结构是什么”；
- `theorem`：回答“在什么假设下能推出什么结论，以及为什么成立”，同时覆盖值得独立引用的定理、命题和引理；
- `method`：回答“一类问题如何系统求解、证明或构造”。

## area 建议值

`mathematics`、`foundations`、`linear-algebra`、`calculus`、`analysis`、`algebra`、`topology`、`geometry-topology`、`differential-geometry`、`probability-statistics`、`differential-equations`、`numerical-mathematics`、`optimization`、`mathematical-physics`、`interdisciplinary`。

## status 规范

### 概念成熟度

`初见` → `可复述` → `可计算` → `可证明` → `可应用`

发现错误时使用 `待修正`。

### 工作流状态

`seed`、`active`、`open`、`answered`、`todo`、`doing`、`done`、`reading`、`unread`、`archived`。

## 属性命名

- 使用小写英文和下划线，例如 `source_type`、`source_map`。
- 避免同一概念出现多种拼写。
- 链接属性使用带引号的字符串列表：

```yaml
prerequisites:
  - "[[20 Concepts/00 Foundations/向量空间与线性映射|向量空间与线性映射]]"
  - "[[20 Concepts/00 Foundations/多元链式法则与Jacobian|多元链式法则与Jacobian]]"
```
